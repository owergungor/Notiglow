# Security Policy

The NotiGlow project takes security and user privacy seriously. As a desktop companion application that interacts with Windows notification mechanisms, ensuring safe execution and zero leakage of user data is paramount.

---

## 🛡️ Supported Versions

Only the latest stable release line receives security patches and updates:

| Version | Supported |
|---|---|
| 1.0.x | :white_check_mark: |
| < 1.0.0 | :x: |

---

## 🚨 Reporting a Vulnerability

If you discover a potential security vulnerability in NotiGlow, please **do not open a public GitHub issue**. Publicly disclosing an unpatched vulnerability exposes users to unnecessary risk.

### Preferred Method: GitHub Security Advisories
Please report vulnerabilities privately via GitHub Security Advisories:

👉 **[Submit a Private Security Advisory](https://github.com/owergungor/NotiGlow/security/advisories/new)**

### What to Include in Your Report
To help us evaluate and address the issue efficiently, please include:
1. **Description**: A clear summary of the potential security risk or vulnerability.
2. **Impact**: How this vulnerability affects users (e.g., privilege escalation, denial of service, memory safety).
3. **Reproduction Steps**: A detailed proof-of-concept (PoC) or step-by-step instructions to reproduce the issue.
4. **Environment**: Windows version, build number, and NotiGlow version tested.
5. **Proposed Fix**: Any suggested patches or mitigations, if known.

---

## ⏱️ Response Timeline

- **Initial Acknowledgment**: We strive to review and acknowledge all private security reports within **48 to 72 hours**.
- **Assessment & Fix**: If the vulnerability is confirmed, we will collaborate on a fix and release a patched version as promptly as possible.
- **Coordinated Disclosure**: A security advisory and acknowledgment will be published once the patch has been released.
